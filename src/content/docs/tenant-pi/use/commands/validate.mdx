`validate` checks the overlay offline. It checks the structure, the supported-input rules and the place of the target. It writes nothing.

Run it after each edit of the overlay. The section [Output](#output) shows the command and its result.

## Options

<Capture id="tenant-pi/help-validate" />

| Option | Meaning |
| --- | --- |
| `--overlay <file>` | Required. The overlay file. |
| `--registry <file>` | A JSON file with the thinking levels of each model that you confirm. |
| `--require-role <role>` | Marks one role as required. Repeat the option for more roles. |
| `--local-dir <dir>` | The absolute directory that holds the input files of the overlay. The default is `.local` in the kit clone. |
| `--manifest <file>` | Another manifest file. The default is `config/manifest.json` of the kit. |

Add an option only when the overlay needs it:

- Give `--registry` when `modelRoutes` of the overlay names a model for a role or for the cycle.
- Give `--local-dir` when the overlay enables the `mcp` component. The action then reads `inputs/mcp-adapter.json` from that directory.
- The roles are `interactive`, `review`, `worker`, `research` and `memory`.
- The action validates a `--manifest` override with the same strict rules.

The registry has this whole shape:

```json
{"<provider>": {"<model>": ["<thinking level>"]}}
```

The registry is a record of your choice. It is not a model catalog, and it is not the Pi file `models.json`.

`validate` does not stop for a required role that the overlay does not set. `plan` then shows the gap `required_role_missing`.

`validate` does not take the options `--launcher`, `--runtime-report` and `--herdr-report`. They belong to [`plan`](/tenant-pi/use/commands/plan/) and [`generate`](/tenant-pi/use/commands/generate/).

## What it reads

| File | When |
| --- | --- |
| The overlay | Always. |
| The manifest | Always. |
| The registry | When you give `--registry`. |
| `inputs/mcp-adapter.json` under `--local-dir` | When the overlay enables `mcp`. |

The action reads each file through one bounded loader:

- The file is a regular file of 1 MiB at most.
- The loader follows no symbolic link.
- The loader refuses JSON with more than 64 nesting levels.
- The loader refuses a JSON object that repeats a key.

The action starts no process and opens no network connection. It reads no credential file.

It reads two environment values, for the place of the target only:

- `HOME`, to find the live profile `~/.pi/agent` and the vault `~/.llm-wiki`.
- `WIKI_HOME`, to find the vault `<WIKI_HOME>/.llm-wiki`.

To compare the target with these places, the action resolves the symbolic links of the paths. It opens no file there.

## The place of the target

After the overlay passes its rules, the action refuses a `target.agentDir` in one of these places:

| Place | Diagnostic |
| --- | --- |
| The kit clone, or a path under it | `under_kit: overlay.target.agentDir` |
| The sample target of `config/config.example.json` | `sample_target: overlay.target.agentDir` |
| The live profile `~/.pi/agent`, or a path under it | `under_pi_agent: overlay.target.agentDir` |
| An LLM Wiki vault, or a path under it | `under_wiki_vault: overlay.target.agentDir` |

The vaults are `~/.llm-wiki`, `<WIKI_HOME>/.llm-wiki` and `<wikiHome>/.llm-wiki` of `memory.wiki.wikiHome` in the overlay.

`plan` and `generate` apply the same four rules. An overlay from `init-private` without `--target` has the sample target.

## Output

<Capture id="tenant-pi/cmd-validate" />

`"valid": true` means that the overlay passes the offline rules. It does not prove that Pi can start the profile.

## Exit codes

| Exit code | Meaning |
| --- | --- |
| 0 | The overlay is valid. |
| 2 | The action refuses the input. Standard error has one JSON object with the rule and the field. |

## Input file errors

Each JSON input of the kit goes through the same loader. The rule names one cause, and the field names the input. The field is `overlay.file`, `manifest.file`, `registry.file` or `mcp.file` for this action.

| Rule | Cause |
| --- | --- |
| `input_path` | The path has a `.` or `..` segment. |
| `input_missing` | The file, or a directory of its path, does not exist. |
| `input_path_unsafe` | A directory of the path is a symbolic link or is not a directory. |
| `input_unreadable` | The system refuses the read, for example because you have no read permission. |
| `input_not_regular` | The last name of the path is a symbolic link, a directory or another entry that is not a regular file. |
| `input_too_large` | The file is larger than 1 MiB. |
| `input_encoding` | The file is not UTF-8 text. |
| `invalid_json` | The text is not valid JSON. |
| `input_too_deep` | Objects and arrays nest deeper than 64 levels. |
| `duplicate_key` | An object has the same key two times. The field is `JSON object`. |
| `number` | The text has `NaN` or `Infinity`, or an integer with too many digits. |

With `invalid_json`, the error object has two more keys: the integers `line` and `column`. They give the first character that the parser refuses. For a missing comma, the cause is often at the end of the line before.

To check the syntax of a file without the kit, run `python3 -m json.tool <file> >/dev/null`.

Warning: without `>/dev/null`, `json.tool` prints the whole file when the syntax is correct.

## Common refusals

| Diagnostic | Cause |
| --- | --- |
| A rule of [Input file errors](#input-file-errors) with the field `overlay.file` | The loader cannot use the overlay file. |
| A rule of [The place of the target](#the-place-of-the-target) | The target is in a place that the kit refuses. |
| `home_required: target.home` | `HOME` is not set. |
| `registry_required: registry` | The overlay has `modelRoutes` with a role or a cycle model, and you give no `--registry`. |
| `registry_without_routes: registry` | You give `--registry`, but the overlay has no `modelRoutes`. |
| `blocked_component: overlay.selection.enable` | The overlay enables a component with the manifest status `blocked`. No component of this release has that status. |
| `missing_dependency: overlay.selection.enable` | An enabled component requires a component that is not enabled. |
| `memory_choices_required: overlay.memory` or `overlay.memory.<module>` | The overlay enables a memory module and has no `memory` block, or the block holds `null` for that module. |
| `memory_consent_required: overlay.consent.memoryCapture` | The overlay enables a memory module and has a `memory` block, and `consent.memoryCapture` is `false`. This rule comes before the rule for a `null` module. |
| `remote_memory_disabled: overlay.consent.remoteMemoryWrites` | `remoteMemoryWrites` is `true`, a memory module is enabled, and `openviking` is not enabled. |
| `unknown_fields: overlay` | The overlay has a key that this release does not define. |
