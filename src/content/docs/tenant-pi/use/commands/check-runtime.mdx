`check-runtime` reads the versions of Pi, Node and Python. It compares each version with the requirement in the manifest of the kit. This action and [`check-herdr`](/tenant-pi/use/commands/check-herdr/) are the only actions that start a process.

```sh
python3 scripts/tenant_pi.py check-runtime
```

## Options

<Capture id="tenant-pi/help-check-runtime" />

| Option | Meaning |
| --- | --- |
| `--pi <path>` | The absolute path of the `pi` executable. The default is `pi` on `PATH`. |
| `--node <path>` | The absolute path of the `node` executable. The default is `node` on `PATH`. |
| `--python <path>` | The absolute path of the `python3` executable. The default is `python3` on `PATH`. |
| `--manifest <file>` | Another manifest file. The default is `config/manifest.json` of the kit. |

## What it runs

The action runs one command for each tool that it finds. It runs three commands at most.

| Tool | Command | Environment |
| --- | --- | --- |
| Pi | `pi --version` | The environment of the caller. `PI_CODING_AGENT_DIR` is an empty temporary directory. |
| Node | `node --version` | The environment of the caller. |
| Python | `python3 --version` | The environment of the caller. |

- No shell runs. Each command has a timeout of 20 seconds.
- A bare `pi` command opens the live profile `~/.pi/agent`. The temporary directory prevents that.
- The action removes the temporary directory after the Pi command. This directory is the only write.
- No other command runs: no `npm`, no `git`, no install, no login and no network request.
- The action reads `PATH` to find a tool. It reads no credential file and no `settings.json`.

Not verified: that `pi --version` with `PI_CODING_AGENT_DIR` set writes nothing outside that directory and opens no network connection.

## What it compares

The requirements come from `runtime` in `config/manifest.json`.

| Tool | Manifest key | Requirement in this release | Rule |
| --- | --- | --- | --- |
| Pi | `piVersion` | `1.1.0` | The tested version. An installed version with the same text gives `match`. |
| Pi | `piAcceptedRange` | `>=1.1.0 <1.2` | The accepted range. Another version inside the range gives `untested_in_range`. |
| Node | `nodeRange` | `>=24.0.0 <25` | The version is inside the range. |
| Python | `pythonRange` | `>=3.11` | The version is inside the range. |

A Pi version outside the accepted range gives `mismatch`. The kit tests ran on the tested version only.

A prerelease of the lower bound or of the upper bound is outside the range. For example, `1.1.0-rc.1` and `1.2.0-rc.1` give `mismatch`.

## Output

The report has one entry for each tool: `installed`, `required` and `status`. The Pi entry also has `tested` and `acceptedRange`. Its `required` value is equal to `tested`.

<Capture id="tenant-pi/cmd-check-runtime" />

The capture comes from the capture container. A tool that the container does not have shows the status `missing`.

| Status | Meaning | `installed` |
| --- | --- | --- |
| `match` | Pi has the exact tested version. Node or Python is inside its range. | The version |
| `untested_in_range` | Pi is inside the accepted range, but it is not the tested version. Only Pi has this status. | The version |
| `mismatch` | The version is readable and does not satisfy the requirement. | The version |
| `missing` | The system cannot find or cannot start the executable. | `null` |
| `unparsed` | The command gives no usable version: unknown output, an error exit, or a timeout. | `null` |

Not verified: an output with `untested_in_range`, `mismatch` or `unparsed` from a real Pi. The site has no capture of them.

## The report as a file

[`plan`](/tenant-pi/use/commands/plan/) and [`generate`](/tenant-pi/use/commands/generate/) do not run this action. They read its report from a file.

1. Send the output of `check-runtime` to a file in the private directory.
2. Give the file to `plan` or `generate` with the option `--runtime-report`.

[Stage 4](/tenant-pi/install/stage-4-plan/#the-runtime-report) shows both commands with real output.

- Make the report in the shell that starts Pi.
- Make the report again after each change of Node or Pi. The kit cannot find an old report.
- The file holds the report also when the exit code is 1.

## Exit codes

| Exit code | Meaning |
| --- | --- |
| 0 | Node and Python have the status `match`. Pi has the status `match` or `untested_in_range`. |
| 1 | One tool or more has the status `mismatch`, `missing` or `unparsed`. The report is on standard output. |
| 2 | Bad input, or the removal of the temporary directory fails. Bad input starts no process. |

Exit code 0 means only that the versions satisfy the rules of the manifest. It does not prove that the profile runs.

## Common refusals

| Diagnostic | Cause |
| --- | --- |
| `absolute_path: check-runtime.pi` | `--pi` is not an absolute path. The same rule applies to `--node` and `--python`. |
| `cleanup_failed: check-runtime.tmpdir` | The removal of the temporary directory fails. The directory stays under `TMPDIR`. |

## Limits

- The action checks the tools that the current shell finds. Run it in the shell that starts Pi.
- The action does not check `npm` or Git.
- The action does not check the Herdr application. Use [`check-herdr`](/tenant-pi/use/commands/check-herdr/) for the `herdr` command.
- The action compares only the version of the Pi package. It does not see the versions of the packages that Pi depends on.
- The action does not install or change a version. A `mismatch` is your decision.
